# CLAUDE.md — School Management Information System (multi-tenant SaaS)

The full v1 brief lives outside the repo (`CLAUDE (4).md`, XpertServiz). This file is the working summary plus the
live implementation log. When the two disagree, the brief wins unless §"Implementation status & decisions" says otherwise.

## Non-negotiable rules
1. **Tenant isolation in the database (RLS)**, not just in code. Every tenant-owned table has `tenant_id NOT NULL`, an index leading with it, RLS and ≥1 policy. `tests/rls-leak` fails CI otherwise. A leak is a P0.
2. **No money moves without a balanced ledger entry** in the same transaction (Phase 2). Money = `bigint` minor units + ISO currency, never floats.
3. **No child is tracked without explicit, recorded, revocable consent**, never covertly (Phase 5).
4. **No child is labelled.** Learning profiles are current, human-reviewed, never a diagnosis (Phase 6).
5. AI proposes, a permitted human approves. No ads/trackers in tenant portals or apps. Never real children's data in seeds/tests.
6. Never hard-code the product name; every user-facing string exists in EN **and** UR (lint = `packages/i18n` parity test).
7. When something isn't covered, pick the simplest option that keeps isolation, child safety and the ledger correct, and leave a `// DECISION:` comment.

## Layout
```
apps/web            Next.js 15 — (marketing) (tenant-site) (app) (vendor); host-based routing in src/middleware.ts
apps/mobile         Expo parent + teacher app (standalone install; written, not yet run on a device)
packages/db         supabase/migrations (schema → functions → policies → rpcs → reference data), seed.sql
packages/core       pure TS: money, permissions evaluator, host classification
packages/ui         Slate & Saffron tokens (+ WCAG check), generated apps/web tokens.css
packages/i18n       en/ur catalogues, t(), Roman-Urdu synonyms
packages/validation zod schemas
packages/providers  payment webhooks (HMAC verify → normalise → record), EMV QR builder, bank CSV parser (server-only)
packages/offline    offline write queue + RPC error classifier (mobile)
packages/comms      notification templates (EN/UR), channel/consent/quiet-hours planning, outbox delivery worker
tests/rls-leak      structure + cross-tenant leak + access-control suites (run on PGlite, no Docker needed)
```

## Commands
- `npm test` — all unit + DB tests (migrations are applied to an in-memory Postgres via PGlite).
- `npm run typecheck` — packages and tests.
- `npm run build:web` — set `NEXT_PUBLIC_ROOT_DOMAIN` at build time (middleware inlines it).
- `npm run tokens -w @ilmora/ui` — regenerate `apps/web/src/app/tokens.css` after editing `tokens.ts` (a test fails on drift).

### Phase 3 — gradebook, payroll, comms (DB + workers done and tested; no UI, no mobile app)
- **Gradebook** (`…1400_gradebook.sql`): exams → assessments (class × subject, max marks) → marks. Stage machine `draft → marking → moderation → published` (`set_exam_stage`, `publish_results`). Marks entry is **class-scoped** (`exams.marks.enter` on the assessment's class) and only while `marking`; in `moderation` teachers are locked out and a coordinator changes marks with a mandatory reason (`moderate_mark` → `mark_amendments`). `publish_results` (needs `results.publish`, separate from moderate) refuses while any enrolled student has no mark (absent/excused count as entered), then **freezes a snapshot** (`result_lines`, `result_summaries` with class positions, ties share a rank, excused papers excluded from totals) and queues one `results.published` notification per child. `amend_published_mark` needs *both* keys + reason, rebuilds the snapshot and re-notifies. Editing the grading scale later does not change a published card. `report_card` returns published results only, to the child's guardians or report-card staff. Default grading scale (A1…F) is a placeholder — boards differ (Open Question).
- **Payroll** (`…1500_payroll.sql`): salary components (fixed or % of basic — no tax/EOBI rate is hard-coded), per-staff pay, `prepare_payroll` (HR) → `post_payroll` (a *different* person with `payroll.post`, 2FA; books Dr 50100/50200, Cr 20400 net + 20500 deductions in the same tx) → `mark_payroll_paid` (bank only) ; `void_payroll` reverses a posted run, a paid run cannot be voided. Absent days deduct on a 30-day month; `adjust_payslip` for one-offs on a draft. Staff see only their own payslip, only once posted (`payslips.published`).
- **Comms** (`…1600_comms.sql`, `packages/comms`): guardian contact preferences with recorded consent (WhatsApp opt-in only; SMS on unless switched off; quiet hours), worker API (`claim_outbox` SKIP LOCKED + stale-claim takeover, `complete_outbox` sent/skipped/retry/defer/dead with back-off and 5-attempt dead-letter), per-recipient delivery log so retries never double-send, bilingual templates (`notify.*`), channel fallback. `apps/web/src/app/api/jobs/outbox` runs it (cron secret). **No real WhatsApp/SMS adapter exists** (BSP/gateway are open questions): the job returns 503 unless `NOTIFY_DRY_RUN=1`, so messages are never claimed-and-dropped.
- **Bug found by tests**: `set_contact_prefs` let any parent edit another guardian's preferences because `NOT (NULL OR false)` is NULL in plpgsql. Fixed with `coalesce`; maker-checker comparisons now use `IS NOT DISTINCT FROM`. When writing permission checks in SQL, remember NULL.
- Tests now **204** (DB: leak sweep over every table, fee operations, reconciliation, people-ops, gradebook, payroll, comms; plus providers + comms packages). Each new guard was mutation-checked.

### Decisions / deviations from the brief
- **npm workspaces** instead of pnpm (pnpm not installed on the build machine); trivially swappable.
- **DB tests run on PGlite** (WASM Postgres) with a small Supabase prelude (`tests/helpers/supabase-prelude.sql`) so CI needs no Docker. PostGIS/pgTAP-dependent tests (Phase 5) will need a real Postgres container.
- **Role definitions are copied per tenant** from global `role_templates` rather than `tenant_id NULL` system roles, so `tenant_id NOT NULL` holds everywhere.
- **RLS is ENABLEd, not FORCEd**: security-definer helpers must read membership tables without recursing into their own policies; app traffic never connects as the owner.
- **JWT `tenant_id` is not trusted by itself**: `app.current_tenant_id()` re-verifies active membership (or an open, matching impersonation session) on every request.
- **`--danger` token changed `#FF6B6B` → `#FF7B7B`**: the brief's value is 4.15:1 on `--surface-1`, failing the brief's own AA rule (now 4.59:1).
- **Plan prices are NULL** (Open Question 3); the pricing page must render "Contact us" for NULL.
- `saferoute_child_phone` feature flag exists and stays OFF per tenant until a written legal opinion exists (§7.1).
- Tenants are never hard-deleted (churn → export → scheduled purge job), so the tenants table has no DELETE audit trigger.
- **Ledger is single-currency (tenant base currency)**; multi-currency/FX snapshot (§6.13) is Phase 7.
- **Teacher visibility of students is tenant-wide `students.view`** until a teaching-assignments table exists (Phase 3). Attendance *is* already class-scoped.
- **Voucher fines are a flat amount once per voucher**; the brief's cap/escalation rules come with the reminder ladder.
- **Internal `app.*` functions are revoked from API roles** (hardening migration + a structure test pins the allowlist); every new migration that adds tables must end with `select app.apply_grants();` and list RPC-only tables there, and any migration that adds `app.*` functions must end with `select app.harden_internal_functions();`.
- **Corrections are reversal journals, never edits**: voiding a payment / cancelling a voucher reverses its journals; `reverse_journal` stays limited to manual/treasury entries. Refunds are bank-only so the cashier drawer count stays clean.
- A Python `open(p,'w')` edit crashed mid-write once and truncated a test helper; it was rewritten. Edit files with the Edit/Write tools, not ad-hoc scripts.
